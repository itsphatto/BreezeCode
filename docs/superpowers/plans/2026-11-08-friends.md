# Friends Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add a Friends page to Home where you add people by email (request + accept) and see their online state, open project and current activity.

**Architecture:**
- A dependency-free `src/main/friends.js` talks to Firebase Auth and Cloud Firestore over REST. It signs in with the GitHub or Google token Breeze already holds.
- `main.js` owns the session and exposes `friends:*` IPC.
- A new renderer unit, `friends.ts`, draws the Home → Friends view, polls the list, and pushes this user's presence through a throttle in main.
- Privacy is enforced by `firestore.rules`.

**Tech Stack:** Electron 44 (main: CommonJS JS; renderer: global-script TypeScript compiled by `tsc` in place), Node `fetch`, `node:test`, Firebase Auth REST (`identitytoolkit`, `securetoken`), Firestore REST v1.

**Spec:** `docs/superpowers/specs/2026-11-08-friends-design.md`

## Global Constraints

- No new runtime npm dependencies. Firebase is called with `fetch` only.
- Friends never sees file names, code, prompts or paths. `project` is the folder name, ≤ 80 chars, or `null`.
- `activity` ∈ `'editing' | 'agent' | 'debug' | 'space' | 'idle'`; `state` ∈ `'online' | 'away' | 'offline'`.
- Identity = the verified email of the **active** account, `trim().toLowerCase()`.
- Request doc id = `` `${fromUid}_${sha256hex(toEmail)}` ``.
- Presence throttle: first write immediate, then ≥ 10 000 ms apart, heartbeat every 60 000 ms, `stop()` writes `offline` once (≤ 1 500 ms on quit).
- Polling: 30 000 ms while the Friends view is visible, 120 000 ms while hidden (badge only). A friend counts as offline when `updatedAt` is > 180 000 ms older than the server's `readTime`.
- Client cap: 50 outgoing pending requests.
- Config: `firebase.apiKey`, `firebase.projectId` in `breeze.config.json`; env `BREEZE_FIREBASE_API_KEY`, `BREEZE_FIREBASE_PROJECT_ID` win.
- Copy (exact):
  - "That doesn't look like an email address."
  - "That's you."
  - "Request sent. They'll see it next time they open Breeze."
  - "Add a friend by email to see what they're building."
  - "Friends isn't set up in this build."
  - "Sign in with GitHub or Google to add friends."
  - "Sign in to <provider> again to use Friends."
  - "Couldn't reach Friends. Retrying…"
- IPC failures return `{ error, code }` (like `syncHandle`). Friends never blocks startup or the editor.
- Follow file conventions: renderer `.ts` files are global scripts (no `import`), listed in `tsconfig.json` `files` and loaded with `<script defer>` in `breeze.html`. Compiled `.js` is not committed.

## Review Focus

1. **Email typed with spaces or capitals** (`"  Bob@X.com "`) must match the account `bob@x.com`. Task 3 pins this.
2. **Adding someone twice, or someone who is already a friend,** must not create a second request or an error loop. The first returns `exists`; a repeat send is idempotent. Task 3 pins this.
3. **A friend who has never shared or turned sharing off** has no presence doc. They show as offline, not as an error. Task 3 pins this.
4. **A wrong local clock** must not make friends look offline. Staleness uses Firestore's `readTime`, not `Date.now()`. Task 3 pins this.
5. **Switching account mid-session** must not keep writing presence or reading friends as the old account. Task 2 pins this through `SessionCache`.

### Task 1: Firestore value codec and `FriendsError`

**Files:**
- Create: `src/main/friends.js`
- Test: `test/friends.test.js`

**Interfaces:**
- Produces:
  - `class FriendsError extends Error { code: 'not-configured'|'signed-out'|'reauth'|'invalid-email'|'self'|'exists'|'too-many'|'network' }`
  - `toFields(obj): object`, which turns plain JSON into Firestore `fields`. `Date` becomes `timestampValue`; the sentinel `SERVER_TIME` becomes a field transform; `null` becomes `nullValue`.
  - `fromDoc(doc): { id, ...data }`, which reads `fields` back to plain JSON. Timestamps become ms numbers; `id` is the last path segment.
  - `normEmail(s): string|null`, which trims and lowercases. It returns `null` unless the result matches `/^[^\s@]+@[^\s@]+\.[^\s@]+$/`.
  - `sha256hex(s): string`

- [ ] **Step 1: Write the failing tests.**
  - `'toFields/fromDoc round-trip strings, numbers, booleans, null and nested maps'`: assert `deepEqual(fromDoc({ name: '…/users/u1', fields: toFields(x) }), { id: 'u1', ...x })`.
  - `'fromDoc turns timestampValue into ms'`: `'2026-11-08T00:00:00Z'` → `Date.UTC(2026,10,8)`.
  - `'normEmail trims and lowercases'`: `'  Bob@X.com '` → `'bob@x.com'`. Rejects `'bob'`, `'a@b'`, `''`.
  - `'sha256hex matches node crypto'`: `sha256hex('a@b.co')` equals `crypto.createHash('sha256').update('a@b.co').digest('hex')`.

### Task 3: Friends API over Firestore

**Files:**
- Modify: `src/main/friends.js`
- Test: `test/friends.test.js`

**Interfaces:**
- Consumes: Tasks 1–2
- Produces `friendsApi({ projectId, session: { uid, idToken, email }, fetch, me: { name, avatar } })` with these methods:
  - `upsertProfile() → Promise<void>`
  - `sendRequest(rawEmail) → Promise<{ id }>`. It throws `invalid-email`, `self`, `exists` (already a friend), or `too-many` (≥ 50 outgoing pending). A repeat send to a pending email resolves with the same id and writes nothing.
  - `accept(requestId) → Promise<void>`. One `:commit` with:
    - the request update `{status:'accepted', toUid}`
    - `friends/{me}/list/{them}`
    - `friends/{them}/list/{me}`
    - a delete of `requests/{me}_{sha256hex(theirEmail)}` if it exists
  - `decline(requestId)` and `cancel(requestId) → Promise<void>`
  - `removeFriend(uid) → Promise<void>`. One commit that deletes both list docs and the accepted request, whichever direction it was sent.
  - `writePresence({ state, project, activity }) → Promise<void>`. It sets `updatedAt` with the `REQUEST_TIME` transform and truncates `project` to 80 chars.
  - `list() → Promise<{ friends: Friend[], incoming: Req[], outgoing: Req[], readTime: number }>`, where
    - `Friend = { uid, email, name, avatar, state, project, activity, updatedAt|null }`
    - `Req = { id, email, name, avatar, createdAt }`
- Base URL: `https://firestore.googleapis.com/v1/projects/${projectId}/databases/(default)/documents`. Use `:runQuery` for the requests (`toEmail ==` mine and `status == 'pending'`; `fromUid ==` mine and `status == 'pending'`), and `:batchGet` for presence.

  - `'sendRequest to an existing friend throws exists; repeat pending send writes nothing'` (Review Focus 2)
  - `'sendRequest throws too-many at 50 pending'`

  - `'writePresence truncates project to 80 chars and uses REQUEST_TIME'`
