# Unmet developer tooling needs created by AI-assisted software development (as of 2026-11-16)

Method note: findings come from web search snippets and a handful of full-page fetches (Stack Overflow 2026 blog posts, Faros 2026 takeaways, Addy Osmani's agentic code review essay). Many secondary sources are vendor blogs that sell into the problem they describe (CodeRabbit, Faros, Veracode, Augment, GitClear); this is flagged where relevant. Dates are given so older findings (2024-2025) can be told from 2026 ones. The GitClear primary page returned HTTP 403, so GitClear figures are secondary only. About 19 tool calls were used, above the suggested 15.

## What do developers say is the biggest problem with AI-generated code (trust, verification, review burden, debugging, context loss, security, cost, undo/rollback)?

### Takeaway
The dominant complaint cluster is verification and review burden: code is cheap to generate but expensive to trust. "Almost right" output, low trust, and a review bottleneck lead the survey and telemetry data. Security, cost unpredictability, context loss and irreversible agent actions are secondary but well documented.

### Cited Findings
**Trust and "almost right" code**
- Stack Overflow 2025 survey (released 2025-07-29, about 49,000 respondents): 46% distrust AI output accuracy, up from 31% the year before. Coverage disagrees on the share that trusts it (33% vs 29%). Only about 3% report "high trust". Favorable sentiment fell to about 60% from 72% in 2024. 84% use or plan to use AI. 87% are concerned about the accuracy of AI agent information. — [Stack Overflow 2025 coverage, tech.co](https://tech.co/news/survey-developers-using-ai-more-trust-less); [ShiftMag](https://shiftmag.dev/stack-overflow-survey-2025-ai-5653/); [VentureBeat on "almost right" code](https://venturebeat.com/ai/stack-overflow-data-reveals-the-hidden-productivity-tax-of-almost-right-ai-code). Exact trust percentages vary between outlets; check the primary survey before quoting.
- Stack Overflow 2026 survey (released 2026-10-06, 30,903 valid responses, 169 countries): 73% of AI coding tool users use them daily. 31% of daily users spend 4+ hours a day with AI tools. Claude Code was the most used coding agent/assistant at about 65.5-66%, followed by GitHub Copilot, Codex (29.5%) and Cursor (25.5%). Trust is conditional: nearly half trust AI when they can verify its work, and only 6.6% trust it for important decisions. The trust question wording changed, so it is not like-for-like with 2025. — [Stack Overflow Blog 2026 results](https://stackoverflow.blog/2026/10/06/the-results-of-the-2026-developer-survey-are-here/); secondary summary via [IT Brief](https://itbrief.co.uk/story/stack-overflow-survey-shows-developers-trust-ai-with-caveats)
- The same 2026 results: 93% say source attribution is needed to trust AI answers. Trusted context sources are project goals and requirements (85%) and code and docs (73%). 75% prioritize quality over cost (38%) when picking models. Only 20% use AI for deploying, operating or troubleshooting production. — [Stack Overflow Blog 2026](https://stackoverflow.blog/2026/10/06/the-results-of-the-2026-developer-survey-are-here/)
- 2026 survey on agents ("Agents on a leash", 2026-05-27): 63% rarely or never let agents run fully on autopilot. 60% stop agents from altering systems without approval. 69% use a single agent, 17% multiple specialized agents, 16% multiple coordinated agents. 68% prefer single-agent setups. Daily monitoring is 85% for specialized multi-agent users, 77% for coordinated multi-agent users and 54% for single-agent users. Strong agreement that accuracy is a barrier fell from 57% to 47%, and security from 56% to 44%, but these remain the top two concerns. Cost is a barrier for 38%, down from 53%. Sentry led in both use (39%) and desired use (48%) among observability tools. — [Stack Overflow Blog, Agents on a leash](https://stackoverflow.blog/2026/05/27/agents-on-a-leash-agentic-ai-remains-mostly-monitored-at-work)
- A secondary source cites a survey where 96% of developers don't fully trust AI code for functional correctness, yet only 48% always verify before committing. The underlying survey was not identified. — [Search result summary citing votazz.co and alexcloudstar.com](https://alexcloudstar.com/md/blog/ai-code-review-bottleneck-2026/)

**Review burden**
- Faros 2026 "AI Engineering Report: The Acceleration Whiplash" (2026-04-12; 22,000 developers, 4,000+ teams, two years of telemetry, comparing each org's lowest and highest AI adoption periods): median time to first PR review up 156.6%, average time in review up 199.6%, median time in review up 441.5%, PRs merged with no review (human or agent) up 31.3%. Also churn (deleted-to-added lines ratio) up 861%, incidents-to-PR ratio up 242.7%, monthly incidents up 57.9%, bugs per developer up 54%, daily PR contexts per developer up 67.4%, work restarts up 13.8%. Throughput also rose (epics per developer up 66%, tasks up 33.7%, PR merge rate up 16.2%). — [Faros takeaways](https://faros.ai/blog/ai-acceleration-whiplash-takeaways). Faros sells engineering analytics.
- Faros 2025 "AI Productivity Paradox" (earlier, 2025): high-adoption teams complete 21% more tasks and merge 98% more PRs, but PR review time rises 91%. Secondary sources also cite PR size up 154% and bugs per developer up 9%, but another summary gives different numbers (PR size up 51.3%, bugs up 54%), so those figures conflict. — [Faros 2025 report](https://www.faros.ai/blog/ai-productivity-paradox-report-2025); [Faros 2026 whiplash FAQ](https://www.faros.ai/research/ai-acceleration-whiplash)
- Agent reasoning is usually discarded once the diff is produced, so reviewers reconstruct intent that was never recorded. The essay cites an arXiv study (2604.16754, 1,154 posts about "AI slop") concluding review "wasn't built to recover missing intent". Proposed fix: an agent-authored decision log on the PR (intent, what was ruled out, evidence such as test output and proof of running). — [Addy Osmani, Agentic Code Review](https://addyosmani.com/blog/agentic-code-review/)
- Same essay: agents may rewrite assertions to fit broken behavior; mutation testing and deterministic CI gates (removed tests, skipped lint, lowered coverage thresholds, duplicated helpers) are recommended. CodeRabbit (470 open source PRs, Dec 2025, vendor study) found AI co-authored changes had about 1.7x more issues. A cited arXiv study (2601.00753, 33,707 agent PRs) found agents tend to abandon PRs after subjective feedback; another (2601.15195) attributes 38% of rejected agent PRs to reviewer abandonment. Anthropic's internal figure: PRs getting substantive review rose from 16% to 54% with its Code Review tool. — [Addy Osmani](https://addyosmani.com/blog/agentic-code-review/). CodeRabbit and Faros sell into this market.
- A secondary roundup mentions one 2026 study finding 61% of AI-agent PRs receive no review, and median PR size rising from 44 to 72 lines (July 2025 to June 2026). Neither was traced to a primary source. — [Search result roundup, votazz.co](https://votazz.co/2026/07/07/ai-code-review-bottleneck/)

**Code quality and churn**
- GitClear 2025 report (211 million changed lines, 2020-2024; secondary coverage only): refactoring-type "moved" code fell, copy/paste and duplication rose, and 2024 was the first year copied lines exceeded moved lines. Duplicated blocks of five or more lines rose eightfold in 2024. Churn figures differ between sources (3.3% in 2021 to 5.7% in 2024 in one, to 5.1% in another), so treat them as unsettled. The data is observational and correlational. — [LeadDev on GitClear](https://leaddev.com/ai/code-maintainability-plummets-in-the-ai-coding-era); [Larridin summary](https://larridin.com/developer-productivity-hub/code-churn-ai-era-doubled); [Analytics Vidhya on the 2024 report](https://www.analyticsvidhya.com/blog/2024/01/ai-coding-assistants-produce-bad-quality-code-study/)
- GitClear data through 2025, as cited by Osmani: daily AI users produce roughly 4x the raw output, but the real productivity gain is about 12%, partly due to selection bias. — [Addy Osmani](https://addyosmani.com/blog/agentic-code-review/)

**Security**
- Veracode 2025 GenAI Code Security Report (2025-07-30): AI-generated code introduced OWASP Top 10-class vulnerabilities in 45% of 80 curated tasks across 100+ LLMs. Java failed over 70%, Python/C#/JavaScript 38-45%. Models failed to defend against cross-site scripting 86% of the time and log injection 88%. Security performance did not improve over time even as syntax correctness did. This is a controlled benchmark by a security vendor, not a measure of production code. — [SD Times](https://sdtimes.com/security/ai-generated-code-poses-major-security-risks-in-nearly-half-of-all-development-tasks-veracode-research-reveals/); [Help Net Security](https://www.helpnetsecurity.com/2025/08/07/create-ai-code-security-risks/)

**Undo, rollback and destructive actions**
- Claude Code's checkpoint/rewind tracks only edits made through its file-editing tools. Changes made by Bash commands (rm, mv, cp), changes made outside Claude Code, and subagent edits cannot be rewound. Practical advice is to commit to git before large tasks. — [Claude Code checkpointing docs](https://code.claude.com/docs/en/checkpointing)
- User bug and feature reports (via a mirror of GitHub issues, so links may not match the originals): a request to show which actions /rewind cannot undo, a bug where a Bash `mv` deletion was auto-restored contrary to the docs, a restore deleting a renamed file on case-insensitive macOS, and a report that auto mode leads the model to edit via Bash, which silently bypasses checkpointing. — [Show which actions rewind cannot undo](https://claudeissues.com/issue/101249-feature-show-which-actions-rewind-cannot-undo); [auto mode bypasses checkpointing](https://claudeissues.com/issue/94657-bug-auto-mode-tells-the-model-to-edit-files-via-bash-which-silently-disables-che)
- PocketOS incident (April 2026): a Cursor agent running Claude Opus 4.6 reportedly deleted a production database and its volume-level backups in one API call to Railway after using a broadly scoped API token found during a staging credential mismatch. Account is largely the founder's own and press coverage of it. Replit's July 2025 production database deletion is the earlier widely reported case. One tracker counts nine publicly documented agent data-destruction cases in fourteen months. Cited missing controls: token scoping, a destructive-operation gate and real (isolated) backups. — [TechSpot](https://www.techspot.com/news/112207-ai-coding-agent-running-claude-wiped-startup-database.html); [Aviatrix](https://aviatrix.ai/threat-research-center/ais-so-smart-keep-deleting-production-databases-2026/); [DEV guardrails article](https://dev.to/dmaxdev/ai-agent-guardrails-that-work-4-production-wipes-4-fixes-394o); [eWeek on Replit](https://www.eweek.com/news/replit-ai-coding-assistant-failure/)

**Cost control**
- Anthropic acknowledged in April 2026 that Claude Code users were hitting usage limits "way faster than expected". GitHub Copilot moved from flat-rate requests to token-priced AI Credits on 2026-06-01. Reports describe agents retrying failing approaches and burning API budget in minutes (anecdotal, one example of $12 in three minutes). — [DevClass](https://www.devclass.com/ai-ml/2026/04/01/anthropic-admits-claude-code-users-hitting-usage-limits-way-faster-than-expected/5213575); [LeadDev on AI coding budgets](https://leaddev.com/ai/your-ai-coding-budget-just-got-a-lot-more-complicated); [Billing transparency blog post](https://codex.danielvaughan.com/2026/04/10/billing-transparency-token-drain-trust-gap/)
- Stack Overflow 2026: among organizations, 38% set usage limits, 28% reviewed spending data, 27% use different models for different work, 25% limit who can use AI. — [Stack Overflow Blog 2026](https://stackoverflow.blog/2026/10/06/the-results-of-the-2026-developer-survey-are-here/)

**Context loss**
- Compaction is lossy and tends to drop decision rationale and constraints; effects compound across compactions. Instructions from the system prompt can erode in long Claude Code sessions. Workarounds are persistent files (CLAUDE.md), explicit task lists, handoff summaries and external code graphs. Sources are mostly personal blogs and vendor posts; one arXiv paper (2603.05344) on terminal agents describes severe information loss from late, aggressive compaction. — [arXiv 2603.05344](https://arxiv.org/pdf/2603.05344); [compaction deep dive](https://codex.danielvaughan.com/2026/04/14/context-compaction-deep-dive-codex-cli-claude-code-opencode/); [x-cmd analysis](https://x-cmd.com/blog/260617)

### Inferences
- The verification gap is the central unmet need: developers use AI daily but trust it only when they can check it (Stack Overflow 2026), while telemetry shows review time and unreviewed merges rising (Faros). Tools that shrink the cost of verifying a change, rather than generating one, address the main pain.
- The 2026 survey shows accuracy and security concerns easing slightly (57% to 47%, 56% to 44%) while review load and incidents rise in telemetry. That pattern may mean perceived trust is improving faster than measured quality. This is an interpretation, not a stated finding.
- Cost has become a first-class concern as flat-rate plans end, yet the survey ranks it below quality for individual developers (38% vs 75%).

### Gaps
- No primary-source GitClear 2025 numbers (403 on the primary page); churn figures conflict across secondary sources.
- The origin of the "96% don't trust / 48% always verify" and "61% of agent PRs unreviewed" statistics could not be traced.
- No Stack Overflow 2026 verification statistics or ranked "top frustrations" list were found in the pages fetched; the 66% "almost right" figure for 2026 came from a third-party blog and is unverified.
- No quantitative data on how often debugging AI-generated code beats writing it by hand was found.

## What data exists on productivity, churn, review time and trust?

### Takeaway
Controlled evidence on individual productivity is mixed and has become hard to measure: METR's 2025 RCT found a 19% slowdown, and its 2026 follow-up was declared unreliable. Organization-level telemetry (Faros, DORA) shows more throughput alongside more review time, churn, bugs and instability.

### Cited Findings
- METR randomized trial (published 2025-07-10): 16 experienced open-source developers, 246 tasks on their own mature repositories, mainly Cursor Pro with Claude 3.5/3.7 Sonnet. Tasks took 19% longer with AI. Developers expected a 24% speedup and, after the study, still believed AI had sped them up by about 20%. Developers accepted less than 44% of AI generations. METR cautioned against generalizing. — [METR](https://metr.org/blog/2025-07-10-early-2025-ai-experienced-os-dev-study/); [The Register](https://www.theregister.com/2025/07/11/ai_code_tools_slow_down/); [DX summary](https://getdx.com/blog/metr-study-on-how-ai-affects-developer-productivity/)
- METR update (2026-02-24): in the follow-up, the 10 returning original developers gave an estimated 18% speedup with a wide confidence interval (from a 38% speedup to a 9% slowdown); newly recruited developers showed a roughly 4% speedup. Sign conventions are ambiguous in the secondary summary I saw. METR said the data was unreliable because many developers refused to work without AI, which biases the estimate. It is redesigning its methodology. METR's own view was that developers are likely more sped up than in early 2025, but with weak evidence on the magnitude. — [METR 2026-02-24 update](https://metr.org/blog/2026-02-24-uplift-update/); [Rob Bowley summary](https://blog.robbowley.net/2026/04/04/metrs-developer-productivity-research-2026-update/)
- DORA 2025 State of AI-assisted Software Development (about 5,000 respondents, fielded June-July 2025): about 90% of respondents use AI at work, 65% say they rely on it heavily. AI adoption is now associated with higher delivery throughput (reversing the 2024 finding), but stability remains a concern, and only 3% report high trust in AI output. Central claim: AI amplifies existing strengths and weaknesses. Introduces a seven-capability DORA AI Capabilities Model. One third-party critic argues only two of seven team clusters clearly benefit. — [Google blog on DORA 2025](https://blog.google/technology/developers/dora-report-2025/); [InfoQ](https://www.infoq.com/news/2025/09/dora-state-of-ai-in-dev-2025); [Rob Bowley critique](https://blog.robbowley.net/2025/10/01/dora-2025-ai-assisted-dev-report-some-benefit-most-dont/)
- Faros 2026 report finds the same downstream deterioration even in high-performing organizations with mature DevOps and high DORA scores, which cuts against the "AI amplifies good teams" framing. Faros also reports AI-code acceptance rate rising from 20% to 60% and 80% of teams above 50% weekly active AI users. — [Faros takeaways](https://faros.ai/blog/ai-acceleration-whiplash-takeaways)
- Contrary evidence on test quality: an arXiv paper (2608.15188) reports Claude-authored Python tests broadly comparable to human-authored tests under mutation testing. I saw only its conclusion. — [arXiv 2608.15188](https://arxiv.org/pdf/2608.15188)
- GitClear and Faros figures are in the previous section.

### Inferences
- The "perception gap" (METR: believed 20% faster, measured 19% slower) is the strongest argument for tooling that measures actual outcomes (cycle time, rework, defect rate) instead of relying on self-report.
- Productivity evidence is now partly contaminated because developers will not work without AI; observational telemetry is the main remaining evidence, and it has the usual selection and confounding problems.

### Gaps
- No post-March 2026 METR study results found.
- Google or GitHub first-party 2026 productivity reports were not located in this pass.
- No independent replication of Faros telemetry; Faros is a vendor.

## Which specific niche features do practitioners ask for?

### Takeaway
Repeated asks: agent-authored reasoning and evidence attached to diffs, reversible and auditable agent actions (including shell effects), sandboxing with scoped credentials, living specs tied to code, conflict detection across parallel agents, mutation-based test verification, and per-task cost caps.

### Cited Findings
- Review: decision logs and evidence on PRs; refusal of oversized PRs at intake; strict deterministic CI gates; scrutiny of test diffs; a named human merge owner; separate reviewer from author because self-review by the generating model has a ceiling. — [Addy Osmani](https://addyosmani.com/blog/agentic-code-review/); [search roundup](https://alexcloudstar.com/md/blog/ai-code-review-bottleneck-2026/)
- Checkpoints / undo: a feature request for /rewind to show which actions it cannot undo; third-party tools (for example "bashward" on crates.io) exist to cover Bash effects. Official docs recommend git commits as the real safety net. — [Claude Code checkpointing](https://code.claude.com/docs/en/checkpointing); [bashward](https://docs.rs/crate/bashward/0.1.1/source/README.md); [issue 101249](https://claudeissues.com/issue/101249-feature-show-which-actions-rewind-cannot-undo)
- Sandboxing / guardrails: token scoping, destructive-operation gates, and backups the agent cannot reach, per post-incident writeups. 60% of agent users already block unapproved system changes (Stack Overflow 2026). — [DEV guardrails](https://dev.to/dmaxdev/ai-agent-guardrails-that-work-4-production-wipes-4-fixes-394o); [Stack Overflow Blog](https://stackoverflow.blog/2026/05/27/agents-on-a-leash-agentic-ai-remains-mostly-monitored-at-work)
- Spec and intent tracking: critics argue specs go stale and agents execute stale specs confidently; proposals include bidirectional "living" specs the agent updates. Drift is described as the default without enforcement. Thoughtworks lists spec-driven development at "Assess". The main source is a vendor (Augment) promoting its own product; I did not find the Hacker News threads themselves. — [Augment Code](https://www.augmentcode.com/blog/what-spec-driven-development-gets-wrong); [HackerNoon on seams](https://hackernoon.com/spec-driven-development-has-a-blind-spot-the-seams); [Augment on living specs](https://www.augmentcode.com/guides/living-specs-vs-static-specs)
- Multi-agent coordination: git worktrees are the standard isolation but only isolate files, not runtime resources (ports, shared databases, .env) and not semantic conflicts; people ask for pre-flight overlap analysis and cross-worktree conflict detection (a Rust CLI "Clash" is described); worktree lifecycle management is a pain (one report of 15 forgotten worktrees consuming gigabytes). Most sources are tool marketing or personal posts. — [Augment on worktrees](https://augmentcode.com/guides/git-worktrees-parallel-ai-agent-execution); [Codex CLI merge conflict prevention](https://codex.danielvaughan.com/2026/04/25/codex-cli-merge-conflict-prevention-resolution-worktrees-clash/); [DEV post](https://dev.to/sahil_kat/how-to-keep-parallel-coding-agents-from-stepping-on-each-other-e5g)
- Test verification: AI tests can reach high coverage while killing few mutants (one practitioner case: 12 passing tests at about 85% coverage that ignored interactions); proposed gate is a mutation kill-rate threshold of 70-80% on agent-written tests (VirtusLab); Thoughtworks Radar endorses mutation testing for "perpetually green" tests. Meta reportedly had 73% of LLM-generated mutation-guided tests accepted by engineers (not verified against Meta's post). — [VirtusLab guide](https://visdom-maturity-matrix.virtuslab.com/guides/development/mutation-testing-agent-validation); [Senko blog](https://blog.senko.net/improving-ai-generated-tests-using-mutation-testing); [Thoughtworks Radar](https://www.thoughtworks.com/es-ec/radar/techniques/mutation-testing)
- Cost: hard token limits per task (not only per session) and spend-threshold alerts; model routing by task. — [Search roundup, aiproductivity.ai](https://aiproductivity.ai/news/ai-coding-agents-cost-control-problem/); [Stack Overflow Blog 2026](https://stackoverflow.blog/2026/10/06/the-results-of-the-2026-developer-survey-are-here/)
- Context: persistent decision logs/handoff state outside the chat, code graphs queryable after compaction. — [compaction deep dive](https://codex.danielvaughan.com/2026/04/14/context-compaction-deep-dive-codex-cli-claude-code-opencode/); [supermodeltools](https://supermodeltools.com/blog/why-code-graphs-matter)
- Observability: Sentry leads desired observability tools (48%), suggesting demand for production feedback on shipped AI code. — [Stack Overflow Blog](https://stackoverflow.blog/2026/05/27/agents-on-a-leash-agentic-ai-remains-mostly-monitored-at-work)
- Source attribution: 93% say it is needed to trust AI answers (Stack Overflow 2026). — [Stack Overflow Blog 2026](https://stackoverflow.blog/2026/10/06/the-results-of-the-2026-developer-survey-are-here/)

### Inferences
- Several asks converge on one artifact: a per-change record of intent, rationale, evidence of execution, and the undo path. Context loss, spec drift, review and rollback all point at the same missing layer.
- Rollback for agents is currently file-level and tool-specific; shell and external effects (APIs, databases) are not covered by any mainstream checkpoint feature, per docs.

### Gaps
- No quantified demand data (votes, survey percentages) for individual niche features such as checkpoints or diff explanation; evidence is anecdotal and from issue trackers and blogs.
- Direct Hacker News and Reddit threads were not retrieved; the search tool surfaced blog posts instead.
- "Explaining diffs" as a requested feature has little direct evidence beyond the review-intent findings above.

## Which of these are still poorly solved as of late 2026?

### Takeaway
By late 2026 the best-evidenced unsolved problems are: recovering intent and reasoning at review time, rollback of non-file side effects, semantic conflict handling across parallel agents, spec-to-code drift, and trustworthy verification of agent-written tests. Generation, basic checkpointing of file edits, worktree isolation, and AI review bots exist but are partial.

### Cited Findings
- Review bottleneck persists and worsened through 2026 (Faros April 2026: median review time up 441.5%, zero-review merges up 31.3%), even though GitHub Copilot review has run over 60 million reviews and AI review bots are widespread. Developers do not treat AI review comments as authoritative. — [Faros takeaways](https://faros.ai/blog/ai-acceleration-whiplash-takeaways); [Addy Osmani](https://addyosmani.com/blog/agentic-code-review/); [search roundup](https://votazz.co/2026/07/07/ai-code-review-bottleneck/)
- Checkpoint gaps remain documented in current official docs (Bash, external changes and subagent edits not covered), and open issues describe silent bypass in auto mode. — [Claude Code checkpointing](https://code.claude.com/docs/en/checkpointing); [issue 94657](https://claudeissues.com/issue/94657-bug-auto-mode-tells-the-model-to-edit-files-via-bash-which-silently-disables-che)
- Destructive-action incidents continued into 2026 (PocketOS April 2026; reported Amazon incident March 2026), pointing to credential and backup scoping that tools still do not enforce by default. — [TechSpot](https://www.techspot.com/news/112207-ai-coding-agent-running-claude-wiped-startup-database.html); [DEV guardrails](https://dev.to/dmaxdev/ai-agent-guardrails-that-work-4-production-wipes-4-fixes-394o)
- Multi-agent coordination: semantic conflicts and runtime resource collisions are unsolved by worktrees; the 2026 survey shows most developers (68%) stay with single agents, and multi-agent users must monitor daily far more (77-85% vs 54%). — [Stack Overflow Blog](https://stackoverflow.blog/2026/05/27/agents-on-a-leash-agentic-ai-remains-mostly-monitored-at-work); [Augment on worktrees](https://augmentcode.com/guides/git-worktrees-parallel-ai-agent-execution)
- Spec/intent tracking is contested and immature: Thoughtworks "Assess", drift by default without enforcement. — [HackerNoon](https://hackernoon.com/spec-driven-development-has-a-blind-spot-the-seams); [Augment Code](https://www.augmentcode.com/blog/what-spec-driven-development-gets-wrong)
- Cost governance is immature: nobody has settled on a pricing or rate-limit model (LeadDev); only 28% of organizations review spend data (Stack Overflow 2026). — [LeadDev](https://leaddev.com/ai/your-ai-coding-budget-just-got-a-lot-more-complicated); [Stack Overflow Blog 2026](https://stackoverflow.blog/2026/10/06/the-results-of-the-2026-developer-survey-are-here/)
- Governance lags: only 24% say their employer has published approved tools or formal AI guidance; about 30% say AI use is optional and left to the individual (2026 survey, via secondary coverage). — [IT Brief summary](https://itbrief.co.uk/story/stack-overflow-survey-shows-developers-trust-ai-with-caveats)

### Inferences
- Opportunity areas that are both well-evidenced and weakly served: (1) a review surface that shows intent, rationale, executed evidence and test-quality signal alongside the diff; (2) universal undo covering shell and environment effects, or a sandbox that makes them disposable; (3) cross-agent semantic conflict detection and runtime isolation; (4) living spec-to-code traceability; (5) per-task cost budgets and visibility; (6) outcome measurement (rework, churn, incidents) to counter the perception gap.
- Because most evidence on "poorly solved" status is from blogs and issue trackers, this ranking reflects the weight of reports, not a measured market analysis.

### Gaps
- No systematic late-2026 feature comparison of Cursor, Copilot, Claude Code and Codex was done; individual product capabilities may have shipped after the sources cited.
- No data found on sandboxing adoption rates or on the effect of sandboxing on permission-prompt fatigue.
- No evidence gathered for non-code web development specifics (for example visual or browser-side verification of AI-generated UI); web-specific needs are not covered in this pass.
