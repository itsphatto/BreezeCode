# Niche tooling gaps specific to web development (as of 2026-11-16)

Method note: ~19 search/fetch calls. Primary pages were fetched where possible (stateofcss.com, web.dev, WebAIM, Chrome DevTools blog, Edge blog). Many tool/market claims come from vendor blogs and secondary write-ups; these are flagged. Several searches returned no official numbers for areas the objective asked about (State of HTML 2025 results, MDN 2025 needs assessment, env-parity surveys). Those are listed under Gaps rather than filled with guesses.

## 1. What do State of JS / CSS / HTML, web.dev, MDN and Interop say about top pain points?

### Takeaway
Browser-support/interop pain is shrinking in share but is concentrated in a handful of newer features (anchor positioning, scroll-driven animations, view transitions) that Interop 2026 now targets. In State of JS 2025 the largest self-reported pains are architecture/state/dependency management, not browser bugs. Debugging, build tools, dependency management and typing all appear as top-10 pain points. Accessibility is getting worse in measurable terms (WebAIM), which is the strongest quantified evidence of a tooling failure.

### Cited Findings
- State of CSS 2025, "general CSS pain points" (419 respondents). Browser support is #1 with 41 mentions (~10%, which the survey calls "a testament to recent improvements"). Others: speed of change 16, excessive complexity 15, Safari 14, excessive Tailwind 13, hard-to-remember syntax 12, Debugging 12, conditional logic 11, layout and positioning 10 — [State of CSS 2025 usage](https://2025.stateofcss.com/en-US/usage/)
- State of CSS 2025, "browser incompatibilities" (537 respondents). Anchor Positioning 106, scroll-driven animations 50, View Transition API 49, generic browser support 37, Safari issues 30. The share citing anchor positioning "almost doubled". CSS Nesting and :has() dropped off because they are now supported in all major browsers — [State of CSS 2025 usage](https://2025.stateofcss.com/en-US/usage/)
- State of CSS 2025, "missing features". Mixins 48, masonry 39, conditional logic 30, nesting 19, for loops 17. The survey notes these are "long possible using workarounds such as preprocessors or JavaScript" — [State of CSS 2025 usage](https://2025.stateofcss.com/en-US/usage/)
- State of JS 2025 "all respondents" pain points (top 10 visible). Code Architecture 3,777; State Management 3,461; Managing Dependencies 3,176; Date Management 2,649; Performance 2,554; Build Tools 2,274 (rank 6); Debugging 2,159; Typing 1,902; Finding Packages 1,289; Async Code 1,104. Testing, frameworks and back-end counts were hidden behind "Show All" and I could not retrieve them — [State of JS 2025 usage](https://2025.stateofjs.com/en-US/usage/)
- State of JS 2025 build tools. Vite 84% usage with 98% satisfaction. Webpack 87% usage but only 26% satisfaction (down from 36%). Rolldown rose from 1% to 10%. Turbopack 28% usage — [InfoQ](https://www.infoq.com/news/2026/03/state-of-js-survey-2025)
- State of JS 2025 language. "Lack of static typing" is the top language pain point. 40% write exclusively TypeScript (34% in 2024) and 6% use plain JS only. Node.js 90% usage, Bun 21%, Deno 11%. Developer happiness flat at 3.8/5 for five years — [InfoQ](https://www.infoq.com/news/2026/03/state-of-js-survey-2025)
- State of JS 2025 frameworks. Next.js had only 21% positive and 17% negative sentiment but drew the most comments (one respondent: "the Next complexity has gotten absurd"). Webpack legacy code was called hard to work with — [InfoQ](https://www.infoq.com/news/2026/03/state-of-js-survey-2025)
- State of JS 2025 AI tooling. Claude usage doubled 22%→44%, Cursor 11%→26%, ChatGPT fell 68%→60% — [InfoQ](https://www.infoq.com/news/2026/03/state-of-js-survey-2025)
- A secondary write-up of State of JS framework pain points (unverified against the official site): React issues 601 mentions, excessive complexity 435, performance 239, state management 217, choice overload 215, out of 3,748 who listed struggles. Sample-size figures conflict across write-ups (13,002 vs 25,000+) — [Plain English write-up via search](https://javascript.plainenglish.io/the-state-of-javascript-2025-survey-result-is-out-the-javascript-framework-wars-are-over-9a34d1229b58)
- Interop 2026 (Apple, Google, Igalia, Microsoft, Mozilla): 18 focus areas, 4 investigation efforts. Survey-identified from State of HTML and State of CSS "top interop issues": anchor positioning, container style queries, dialogs/popovers, scroll-driven animations, view transitions. Others include attr(), contrast-color(), custom highlights, navigation API, scroll snap, shape(), zoom, WebRTC, WebTransport, web-compat items — [web.dev Interop 2026](https://web.dev/blog/interop-2026)
- Interop 2026 investigation efforts (not yet focus areas): accessibility testing (consistent accessibility trees across browsers, WPT infrastructure), JPEG XL, mobile testing infrastructure (e.g. dynamic viewport), WebVTT — [web.dev Interop 2026](https://web.dev/blog/interop-2026)
- Edge's Top Developer Needs dashboard (2024, refreshed June 2025, 2026 edition live March 2026) tracks long-running interop issues Interop does not cover. Edge acknowledged developers find Interop's selection process "opaque". Past items that fed Interop: Custom Highlights, field-sizing, scroll-driven animations, Trusted Types. No survey figures in the post — [Microsoft Edge and Interop 2026](https://blogs.windows.com/msedgedev/2026/02/12/microsoft-edge-and-interop-2026/)
- Interop 2027 proposals call was posted 2026-09-03 (title seen in search results only; content not read) — [Windows Blogs](https://blogs.windows.com/msedgedev/2026/09/03/calling-for-interop-2027-proposals/)
- MDN's Developer Needs Assessment: the latest edition I found was 2020 (2019 baseline). Browser compatibility was the top theme, with 4 of the top 5 needs relating to it. Satisfaction with browser compatibility was 44% vs almost 75% for the web overall. Old evidence, outside the 2025-26 window — [MDN Browser Compatibility Report 2020](https://mdn.dev/archives/insights/reports/mdn-browser-compatibility-report-2020.html)
- WebAIM Million 2026 (Feb 2026): 95.9% of home pages had detected WCAG 2 failures (94.8% in 2025). Average 56.1 errors/page (51 in 2025). Low contrast 83.9%, missing alt 53.1%, missing form labels 51%, empty links 46.3%, empty buttons 30.6%, missing language 13.5%. These six categories are 96% of detected errors and have led for seven years. ARIA pages averaged 59.1 errors vs 42 without. 133+ ARIA attributes per page (up 27%). The report links rising errors to "automated or AI-assisted coding practices" and "vibe coding" — [WebAIM Million](https://webaim.org/projects/million/)
- WebAIM by framework: Astro 9.0 errors avg, Next.js 40.9, React 43.5, AngularJS 76.6, Firebase 82.9; jQuery pages 64.9 — [WebAIM Million](https://webaim.org/projects/million/)
- Stack Overflow 2025 survey (AI): 66% cite "AI solutions that are almost right, but not quite" as top frustration; 45% say debugging AI code is more time-consuming; 46% distrust AI accuracy. One summary gives 45% for the "almost right" figure, which looks like an error — [Stack Overflow blog](https://stackoverflow.blog/2025/07/29/developers-remain-willing-but-reluctant-to-use-ai-the-2025-developer-survey-results-are-here), figures via [Tech.co summary](https://tech.co/news/survey-developers-using-ai-more-trust-less)
- Secrets: GitGuardian 2026 report (Mar 2026): ~28.65M new hardcoded secrets in public GitHub commits in 2025 (+34% YoY). AI-service secret leaks +81%. Claude Code-assisted commits leaked at 3.2% vs 1.5% baseline. 24,008 unique secrets in MCP config files (2,117 valid). 64% of secrets valid in 2022 were still exploitable in Jan 2026. Secondary coverage only — [The Hacker News](https://thehackernews.com/2026/03/the-state-of-secrets-sprawl-2026-9.html), [GitGuardian blog](https://blog.gitguardian.com/the-state-of-secrets-sprawl-2026/)
- Flaky tests: the best-sourced developer evidence is old. Eck et al. 2019 survey found 79% of 121 respondents consider flakiness a moderate to serious problem, and 59% deal with it monthly or more. Currents CI telemetry (vendor) puts average flake rates at 0.72% Playwright vs 0.83% Cypress — [arXiv 2203.00483](https://arxiv.org/abs/2203.00483), [Currents](https://currents.dev/posts/cypress-vs-playwright-flakiness-comparison)
- The widely repeated "15-25% of E2E tests are flaky" figure is attributed to Google 2016 in a vendor blog that aggregates other stats without methodology. Treat as unverified — [Diffie vendor report](https://diffie-ai.pages.dev/blog/state-of-e2e-testing-2026)

### Inferences
- State of JS counts show "Managing Dependencies" (3,176) and "Debugging" (2,159) as large, tool-addressable pains. They sit alongside architecture and state, which are less tool-addressable.
- Cross-browser pain has narrowed to a short list of new CSS/DOM features. The gap is no longer "does CSS work" but "will this new feature work in my browser matrix, and what is the fallback". A tool that gives feature-by-feature baseline/fallback guidance in-editor is a plausible niche, but Baseline already exists (see Q3).
- Accessibility is the only area with consistent, large-sample, year-over-year measured regression, and a named link to AI-assisted code. That makes it the best-evidenced severity signal in this research.

### Gaps
- State of HTML 2025 results (pain points, forms, a11y): the search returned only the 2024 edition and survey-design commentary. The official 2025 results were not retrieved.
- State of JS 2025 testing, back-end and "other tools" pain-point counts are hidden behind "Show All" on the page and were not retrieved.
- No 2025-26 MDN Developer Needs Assessment found. Web DNA 2019/2020 is the latest located.
- No credible 2025-26 developer survey with a percentage for env/config drift or local-vs-prod parity was found.

## 2. Which candidate gaps lack a good integrated tool (editor, DevTools, CI)?

### Takeaway
Most candidates have point solutions, but integration across editor, runtime and CI is thin. The clearest "no good integrated tool" findings are (a) DOM-to-source mapping in mainstream DevTools, (b) dependency-upgrade impact analysis (bots bump versions and rely on CI), and (c) rendered-state a11y feedback in the editor (linters are static-only). Type-safe contract checking and session replay are relatively well covered. Flaky-test diagnosis and prod-parity are mostly vendor-driven with sparse independent evidence.

### Cited Findings
- DOM-to-source mapping. Chrome DevTools AI assistance operates on the inspected DOM element and can write CSS changes back to disk only with a connected workspace. It does not map DOM nodes to framework components or source files. Chrome 149 notes (June 2, 2026) mention no source-mapping or framework-component feature, and say automated styling fixes are being deprecated in Chrome 152 in favour of "copy to coding agent" — [Chrome DevTools AI assistance](https://developer.chrome.com/docs/devtools/ai-assistance/chat), [What's new in DevTools 149](https://developer.chrome.com/blog/new-in-devtools-149)
- DOM-to-source point solutions exist but are framework-specific plugins: LocatorJS (Alt-click opens source in editor; React), react-dev-inspector (needs Babel plugin + dev-server middleware), vite-react-locator, and the `element-source` library (React, Preact, Vue, Svelte, Solid component stack from debug metadata) — [LocatorJS](https://chromewebstore.google.com/detail/locatorjs/dpploomkdkooepkpbdpjkgfnkpfhbbfp), [react-dev-inspector](https://github.com/vagusX/react-dev-inspector)
- A Cursor forum request asks for click-to-source from the built-in browser/visual editor because inspection mainly feeds the element into AI context. I did not confirm whether it has shipped — [Cursor forum](https://forum.cursor.com/t/click-to-source-from-browser-visual-editor-inspect-open-file-line/146166)
- Production bug replay. Two product classes exist. Session replay (Sentry, LogRocket, FullStory, OpenReplay, PostHog) records DOM behaviour. Time-travel debuggers (Replay.io) record runtime so you can add breakpoints after the fact. Replay.io states its runtime recording is hard to do reliably and can diverge. Sources are vendor-authored; no independent 2026 benchmark found — [Replay.io comparison](https://blog.replay.io/session-replay-vs-time-travel-debugging), [Sentry Replay docs](https://docs.sentry.io/product/explore/session-replay/replay-details/)
- In-editor a11y. Deque's axe Linter is static analysis of code (JSX, Vue, Angular, HTML) giving squiggles in VS Code; it cannot judge rendered behaviour, and Deque points to a separate Axe MCP Server for rendered-state guidance. I could not verify any "automated tools catch ~30% of issues" figure — [Deque axe Linter](https://www.deque.com/axe/linters/), [VS Code docs](https://docs.deque.com/linter/axe-linter-vs-code)
- Chrome DevTools has no dedicated a11y feature in release 149 beyond APCA contrast going stable — [What's new in DevTools 149](https://developer.chrome.com/blog/new-in-devtools-149)
- Interop itself lists accessibility testing as only an "investigation effort", i.e. browsers do not yet produce consistent accessibility trees for testing — [web.dev Interop 2026](https://web.dev/blog/interop-2026)
- Dependency upgrade impact. One vendor comparison says Dependabot does not perform breaking-change analysis; it bumps the version and relies on CI. Renovate adds crowdsourced "merge confidence" but neither does context-aware codebase analysis. Vendor sources (Endor Labs, Pixee, FOSSA, Socket) — [Endor Labs](https://www.endorlabs.com/learn/automated-dependency-updates), [Socket glossary](https://socket.dev/glossary/automated-dependency-updates.md)
- Update bots deliver freshly published releases into CI within hours, the window supply-chain attackers use (Socket, vendor). The same source claims npm v12 (July 2026) skips install scripts unless allowed; I did not verify this independently — [Socket glossary](https://socket.dev/glossary/automated-dependency-updates.md)
- One write-up reports an ESLint 10 breakage with an unmerged fix as of July 2026, illustrating ecosystem lag after major bumps — [Classmethod](https://dev.classmethod.jp/en/articles/dependabot-major-bump-ecosystem-lag/)
- An FSE 2026 academic paper on knowledge-based updates of breaking JavaScript dependencies exists; only title/DOI seen, findings not read — [FSE 2026 PDF](https://nesa.zju.edu.cn/download/auto_20260423_yifan-2026fse.pdf)
- API contract drift. OpenAPI diff tooling is plentiful but fragmented: oastools, SpecShield, Breakwatch (created May 2026), FlareCanary, SchemaWatch. A May 2026 comparison says Spectral covers breaking changes only partially. A dev.to post claims Optic was archived on 2026-01-12 (single unverified source). Consumer-driven contract testing (Pact-style) covers response-shape drift that spec diffs miss — [dev.to tools comparison](https://dev.to/flarecanary/api-schema-drift-detection-tools-compared-2026-1ib4), [Optic status claim](https://dev.to/peter_zsobrk_50d5c4ac7de/optic-is-dead-alternatives-for-openapi-breaking-change-detection-dmp)
- Local env parity. Sources are vendor blogs (Upsun, Doppler) framing parity as a "platform problem"; no survey figure. The Doppler-cited claim that private repos are 9x more likely to hold secrets than public ones is secondhand — [Upsun](https://upsun.com/blog/environment-parity-platform-problem), [Doppler](https://www.doppler.com/blog/secure-dev-environments)
- Flaky-test diagnosis. Existing evidence is mostly vendor blogs and benchmark reports (TestDino, Currents, Diffie); no independent 2025-26 survey of web E2E flakiness located — [TestDino benchmark](https://testdino.com/blog/flaky-test-benchmark/)
- Perf regression. Chrome DevTools AI assistance now renders interactive Core Web Vitals / LCP breakdown widgets and can use Lighthouse insights (Chrome 149). The web-vitals library v5.2.0 fixed INP-monitoring memory leaks. A guide notes Playwright remains better for deterministic CI regression tests than DevTools MCP — [What's new in DevTools 149](https://developer.chrome.com/blog/new-in-devtools-149), [Jimmy Song guide](https://jimmysong.io/blog/web-automation-advancement/)

### Inferences
- DOM-to-source: mainstream DevTools stops at the DOM, and a coding-agent hand-off is DevTools' own chosen answer. The mapping layer lives in per-framework plugins, so a framework-agnostic, editor-resident version is a real gap. This does not mean no solution exists: LocatorJS and similar tools cover React.
- Dependency impact: the missing piece is "which of MY call sites does this upgrade touch, and is it safe", not detection of new versions. Supported by vendor claims only; the evidence base is weak independent data.
- A11y: static linting plus post-hoc audits leave a gap for rendered-state feedback during editing (focus order, ARIA state, contrast in context). Supported by Deque's own scoping and WebAIM trends.
- Type-safe contract checking is the least gap-like candidate: many tools plus tRPC/OpenAPI codegen patterns. The remaining gap is cross-repo consumer impact analysis ("who uses this endpoint"), which only young tools (Breakwatch) address.

### Gaps
- No independent evidence found that quantifies how much time web developers lose to DOM-to-source navigation, flaky-test diagnosis, or env parity.
- Optic's archived status and the npm v12 install-script claim rest on single unverified sources.
- No data on adoption rates for session replay vs time-travel debugging among web teams.

## 3. Which have emerging solutions, and how mature are they?

### Takeaway
The hottest emerging layer is agent-facing browser tooling. Chrome DevTools MCP/CLI went stable in June 2026 and DevTools is adding agent hand-offs. Interop and Baseline are maturing for cross-browser issues. Weakest maturity: component-level DOM-to-source in DevTools (nothing native), consumer-aware API drift (new tools of weeks to months of age), and rendered-state a11y feedback (mostly experimental).

### Cited Findings
- Chrome DevTools MCP server and CLI "for agents" are officially stable (v1.1.1) as of Chrome 149, June 2, 2026. Pages can define custom debugging tools in JavaScript that agents discover and call (experimental). DevTools can list and run WebMCP tools (experimental, behind flags) — [What's new in DevTools 149](https://developer.chrome.com/blog/new-in-devtools-149)
- The MCP server's performance trace tool targets LCP, INP and CLS. Tool counts reported vary between 6 and 29 by snapshot or slim mode. Mostly blogs and directories, not changelogs — [Sitebulb guide](https://sitebulb.com/resources/guides/auditing-core-web-vitals-with-chrome-devtools-mcp/), [Continue cookbook](https://docs.continue.dev/guides/chrome-devtools-mcp-performance)
- Chrome DevTools AI assistance can copy conversation as a prompt for a coding agent, and Gemini code completion now covers the Styles tab — [What's new in DevTools 149](https://developer.chrome.com/blog/new-in-devtools-149)
- Interop 2026 and Edge's Top Developer Needs dashboard are mature, institutional answers for cross-browser feature gaps (with an acknowledged transparency complaint) — [Microsoft Edge and Interop 2026](https://blogs.windows.com/msedgedev/2026/02/12/microsoft-edge-and-interop-2026/)
- Session replay is a mature product category with built-in error linking (Sentry surfaces replays for errors with no custom instrumentation). Time-travel debugging (Replay.io) is more powerful but harder to set up and its own docs admit fragility — [Replay.io](https://blog.replay.io/session-replay-vs-time-travel-debugging)
- Rolldown rising from 1% to 10% in State of JS 2025 indicates the build-tool layer is mid-transition to Rust-based tooling — [InfoQ](https://www.infoq.com/news/2026/03/state-of-js-survey-2025)
- Agent-based dependency/impact checkers appear mostly as community "skills" and prompts rather than established products — [AI tools compared](https://theluckystrike.github.io/ai-tools-compared/ai-powered-dependency-update-tools-compared)

### Inferences
- Maturity ladder (my judgment from the above): mature: cross-browser feature tracking, session replay, static a11y linting, OpenAPI diff. Emerging (months-old, vendor-led): agent-driven performance and browser debugging, consumer-aware contract checks, AI dependency impact. None/thin: native component-level DOM-to-source in DevTools; rendered-state in-editor a11y; independently measured flaky-test diagnosis.
- Because Chrome itself is routing styling/source work to external coding agents, the integration point is open for editors and agent-hosting IDEs rather than DevTools.

### Gaps
- No maturity data (users, stars, retention) was collected for the tools named.
- Did not verify whether Cursor's browser or Onlook now ship click-to-source.

## 4. Ranking candidate gaps by breadth and severity, with evidence

### Takeaway
Ranked by my judgment on evidence quality plus breadth. Accessibility feedback is #1 for severity evidence. Dependency impact and DOM-to-source rank next for breadth but have weaker independent evidence. Env parity/secrets is severe but mostly a security rather than a tooling-gap story. Flaky tests and prod repro have the least independent 2025-26 evidence.

### Cited Findings
Ranking table (rank, gap, breadth signal, severity signal, integrated tool today?):
1. Rendered-state a11y feedback while coding. Breadth: 95.9% of top-1M home pages fail (WebAIM 2026). Severity: errors rising, 56.1 per page, AI-assisted code implicated. Tool today: static linters (axe Linter), page scanners; browsers lack consistent a11y trees (Interop investigation). Evidence strength: high — [WebAIM](https://webaim.org/projects/million/), [web.dev Interop 2026](https://web.dev/blog/interop-2026)
2. Dependency upgrade impact analysis. Breadth: "Managing Dependencies" is #3 State of JS pain (3,176 mentions). Severity: breaking changes found after merge; supply-chain window. Tool today: bots plus CI; no codebase-aware impact check (vendor claim). Evidence strength: medium — [State of JS 2025](https://2025.stateofjs.com/en-US/usage/), [Endor Labs](https://www.endorlabs.com/learn/automated-dependency-updates)
3. Debugging and visual-to-source tracing (DOM-to-source, CSS debugging). Breadth: Debugging 2,159 State of JS mentions; Debugging 12 mentions in State of CSS general pains. Tool today: per-framework plugins; DevTools lacks component mapping. Evidence strength: medium-low (indirect) — [State of JS 2025](https://2025.stateofjs.com/en-US/usage/), [State of CSS 2025](https://2025.stateofcss.com/en-US/usage/)
4. Secrets and env/config management. Breadth: 28.65M leaked secrets/yr on public GitHub; AI-assisted commits leak ~2x. Severity: 64% of 2022 valid secrets still live in 2026. Tool today: scanners and secret managers exist; MCP config files are a new leak surface (24,008 secrets). Evidence strength: high on leak volume, but secondary coverage and it is security-heavy — [The Hacker News](https://thehackernews.com/2026/03/the-state-of-secrets-sprawl-2026-9.html)
5. New-CSS-feature cross-browser fallback guidance (anchor positioning, scroll-driven animations, view transitions). Breadth: top browser incompatibility items in State of CSS. Tool today: Interop, Baseline, Edge dashboard (strong institutional coverage), so an in-editor layer is the only gap. Evidence strength: high — [State of CSS 2025](https://2025.stateofcss.com/en-US/usage/), [web.dev Interop 2026](https://web.dev/blog/interop-2026)
6. Performance regression tracing. Breadth: Performance 2,554 State of JS mentions. Tool today: DevTools AI/Lighthouse/MCP now strong; CI regression still better served by Playwright and other tools. Evidence strength: medium — [State of JS 2025](https://2025.stateofjs.com/en-US/usage/), [What's new in DevTools 149](https://developer.chrome.com/blog/new-in-devtools-149)
7. API/contract drift. Breadth: no survey data found. Tool today: many OpenAPI-diff tools; consumer-impact linking is nascent. Evidence strength: low, vendor-only — [dev.to comparison](https://dev.to/flarecanary/api-schema-drift-detection-tools-compared-2026-1ib4)
8. Flaky-test diagnosis. Breadth: 2019 survey 79% see it as moderate-serious; no 2025-26 web-specific survey. Evidence strength: low, vendor-only — [arXiv 2203.00483](https://arxiv.org/abs/2203.00483)
9. Production-bug reproduction and local-vs-prod parity. Session replay is mature; parity evidence is vendor opinion only. Evidence strength: low — [Replay.io](https://blog.replay.io/session-replay-vs-time-travel-debugging), [Upsun](https://upsun.com/blog/environment-parity-platform-problem)

Candidate examples explicitly verified or rejected:
- Visual/DOM-to-source mapping: partly verified as a gap in DevTools; not a total gap because plugins exist.
- Live prod-bug replay: rejected as an unmet need in the basic form (mature products); remaining gap is reliability and integration with the editor.
- Dependency upgrade impact analysis: verified as thin (vendor-supported).
- Type-safe API contract checking: mostly rejected as unmet; the narrower cross-consumer impact piece is open.
- A11y in-editor feedback: verified for rendered-state feedback; static linting is rejected as a gap.
- Flaky-test diagnosis: not verifiable with independent 2025-26 data.

### Inferences
- The strongest candidate for a differentiated IDE-integrated capability is a feedback loop that connects the running page (rendered DOM, a11y tree, computed styles) to the source line and to an AI agent: it combines gaps 1 and 3, which the evidence ties to measurable a11y regression, and fits Chrome's own direction of handing context to external coding agents. This is my synthesis, not a sourced claim.
- Because AI coding agents are blamed for rising a11y errors (WebAIM) and secret leaks (GitGuardian), guardrail tooling at generation time is a recurring theme across independent sources.

### Gaps
- No weighted survey ranking across all candidate pains exists. The ranking above is my judgment.
- Developer time-cost figures for each gap could not be sourced.
- Reddit/HN sentiment was not searched; ranking lacks qualitative practitioner evidence.
